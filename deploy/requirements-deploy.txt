# GET /openapi.json once 500'd with a PydanticUserError,
#   "Body_create_dub_v1_dub_post is not fully defined; ... call .rebuild()"
# We first suspected pydantic >= 2.11, but it reproduces on 2.10 AND 2.12: the cause was never
# a version. deploy/api.py uses `from __future__ import annotations` (PEP 563), so its endpoint
# annotations are strings that FastAPI resolves against the module's globals during schema
# generation — and the fastapi imports were done inside build_api(), so they weren't there.
# The fix is in api.py (import those names at module scope; parse the /v1/dub multipart form off
# the raw Request so no Body_* model is synthesized). The bounds below are therefore just
# conservative guards, not a workaround. On the Modal image f5-tts -> gradio floats
# fastapi/starlette/pydantic forward anyway; that's harmless (we never run gradio; the TTS path
# imports only f5_tts.infer.utils_infer), which is why modal_app.py no longer pins them.
